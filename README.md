# Four of Hearts Interactive website

Public portfolio website for Four of Hearts Interactive, LLC and 4ohi.com.

## Company and games

- Four of Hearts Interactive is the parent brand; 4OH is the approved compact mark.
- Palace is the flagship card game and has a complete, single-game browser edition powered by the production Palace rules engine.
- GildenSpire is a dragon flight adventure in development with no announced release date or public build.
- BooYang City and Funky Town are distinct city-building games in development: one a connected city of mini-adventures, the other a town transformed through art and player expression.
- Bobby the Breadasaurus is a family adventure in concept development.
- Evil Doom Boy is one action-adventure game in development. Evil Doom Boy is the default playable hero; Evil Doom Girl is the alternate playable hero; Evil Doom is the antagonist.
- Thumb Command is an arcade-defense game in development with no announced release date or public build.
- Hearts, Spades, and Euchre remain in internal testing and each has a website lesson.
- Whomly and Sleep Amigo are first-class lifestyle applications in development and are intentionally excluded from the game catalog.
- The reusable product source of truth is `scripts/studio-product-manifest.mjs`.

No page claims an unverified release date, platform, rating, store listing, player count, or public build.

## Architecture

The dependency-free static site is generated by scripts/build-site.mjs from shared navigation, metadata, the catalog, product modules, and content/news.json.

The root route is a Palace-first editorial campaign inside the Four of Hearts Interactive company shell. Global navigation exposes Games, News, About, and Play Palace; the 4OH mark returns Home. The Palace table-name control exists only in palace-play.html. Support remains in the footer and direct route.

Artwork derivatives are built by scripts/process-portfolio-art.py and scripts/process-thumb-command-art.py. Founder source boards remain untouched. See [Portfolio art provenance](docs/PORTFOLIO-ART-PROVENANCE.md).

The site uses no account, backend form, analytics, advertising, tracking pixel, social widget, or remote font. Palace stores one versioned game and sound/motion preferences on the visitor device; the privacy control creates one opt-out cookie only when requested.

## Local preview and validation

    node scripts/build-site.mjs
    python -m http.server 4173 --bind 127.0.0.1
    node scripts/validate-site.mjs
    node scripts/verify-company-architecture.mjs
    node scripts/verify-evil-doom-origin.mjs

Rendered gates cover phone, tablet, laptop, desktop, and mobile landscape. They check keyboard navigation, the complete game lineup, honest statuses, Palace isolation, the complete Palace browser game, three card-game lessons, images, overflow, metadata, spelling, artwork provenance, the one-game Evil Doom identity and accessible hero selector, and zero tracking.

There is no package manifest, so no separate framework lint, type-check, or bundler command exists. Syntax checks, the generator, static validation, and rendered Chromium suites are the production build gates.

## Deployment

Publishing is separate from building. Push a reviewed commit to main, wait for GitHub Pages to deploy the exact SHA, then rerun browser suites against https://4ohi.com.

The CNAME is 4ohi.com. Never alter Proton MX, SPF, DKIM, DMARC, provider verification, or unrelated TXT records during a website release.

## Production portfolio architecture

Requirements: the bundled Node.js runtime and Chromium/Chrome used by the repository's existing QA scripts.

- Develop locally: `python -m http.server 4173 --bind 127.0.0.1`
- Build production files: `node scripts/build-site.mjs`
- Run static validation: `node scripts/validate-site.mjs`
- Run rendered tests: `node scripts/verify-production-portfolio.mjs`
- Run privacy tests: `node scripts/verify-california-privacy.mjs`
- Deploy: commit generated output, push the approved commit to `main`, and wait for the exact-SHA GitHub Pages workflow.

The source of truth is `scripts/studio-product-manifest.mjs`; see `docs/PRODUCT_REGISTRY.md`. To add a game, add a `category: "game"` record with a stable key, group, canonical route, accurate status, approved art, alt text, and CTA. To add a lifestyle app, use `category: "lifestyle"` and `group: "lifestyle-apps"`; it will stay outside `gameCatalog`. `scripts/build-site.mjs` then generates navigation, pages, footer links, structured data, feed, and sitemap.

To add a language, define it in `assets/product-authority.js`, add its `hreflang` code in `scripts/build-site.mjs`, translate persistent interface strings, and add browser coverage proving navigation preserves the query. Canadian copy is centralized in `scripts/production-pages.mjs` and `assets/production-locales.js`; see `docs/LOCALIZATION.md`.

Product tiles are generated by `productTile` and `productCard` in `scripts/production-pages.mjs`. Do not hand-code a tile or use a full concept sheet: add a focused approved asset and provenance first. Asset ownership, source, commercial approval, and derivatives are recorded in `docs/ASSET_PROVENANCE.md` and `docs/asset-provenance.json`.
